# Architectural Decision Record: ADR-003

## Typographic Typesetting Layout and Font Metrics Engines

* **Status**: Approved
* **Date**: 2026-07-09

---

## Context and Problem
Modifying text inside a PDF requires character spacing calculations to match professional PDF viewer layout outputs. 

Relying on browser measurements or PDF.js DOM text overlays leads to visual misalignments and coordinates mismatches, as browser text render heights and spacing behave differently from native PDF design metrics.

---

## Alternatives Considered
1. **Browser MeasureText**: Call browser `ctx.measureText` on canvas.
   - *Con*: Highly dependent on DOM fonts loading, lacks kerning offsets, inconsistent across browsers.
2. **Overlay DOM Inputs**: Place absolute HTML textareas over the canvas.
   - *Con*: Text layout overlaps break during camera zooms or pans, causing visual lag.

---

## Decision and Consequences
We implemented a self-contained typographic layout and typesetting compiler (`FontMetrics`, `GlyphCache`, `Kerning`, `LineBreaker`, `TextLayout`, `CaretEngine`). 

Standard design heights are registered and scaled by font size. Width advance caches and AV pair kerning dictionaries compute character runs in screen space, wrapping words automatically. Clicks map directly to caret insertion indexes and word/line selections.

### Consequences:
* **Pros**: Invariant multi-platform typesetting, server-side compatibility, and precise selection highlights mapping.
* **Cons**: Requires shipping font metrics dictionaries for Helvetica, Times, and Courier inside the engine codebase.
