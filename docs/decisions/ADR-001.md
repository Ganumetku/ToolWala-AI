# Architectural Decision Record: ADR-001

## Decoupled Object Registry and State Snapshots

* **Status**: Approved
* **Date**: 2026-07-09

---

## Context and Problem
Professional PDF editors must allow elements coordinates moves, rotation dragging, and resizing transformations while safeguarding original parameters parsed from raw PDF bytes. 

If mutations rewrite original coordinate matrices directly, the engine loses its ability to calculate relative coordinate shifts (needed for PDF contents streams operator updates) or undo/redo changes.

---

## Alternatives Considered
1. **Direct Mutation**: Mutate parsed properties directly.
   - *Con*: Irreversible. Loses relative matrix shifts and undo support.
2. **Fabric.js Canvas Control**: Delegate layout updates to Fabric's wrapper components.
   - *Con*: High runtime footprint. Tight dependency on canvas rendering engines.

---

## Decision and Consequences
We decoupled core models parsing from drawing/selection layers, routing all updates through a centralized `ObjectRegistry` singleton cache. 

Every object holds three state snapshot levels:
* `originalState`: Read-only snapshot storing parsed PDF coordinates.
* `currentState`: Read-write copy tracking active transformations on canvas viewports.
* `editedState`: Read-write record storing modifications for final PDF exporters.

### Consequences:
* **Pros**: Safe transforms, coordinate isolation, transaction history, clear exporter pipelines.
* **Cons**: Marginally higher memory consumption due to snapshot tracking.
