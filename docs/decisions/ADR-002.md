# Architectural Decision Record: ADR-002

## Hierarchical Page-Layer Scene Graph and Viewport Culling

* **Status**: Approved
* **Date**: 2026-07-09

---

## Context and Problem
Displaying multi-page PDFs with thousands of elements can lead to performance bottlenecks (cluttering memory and slowing canvas redraws). 

If every object renders directly on canvas regardless of scroll visibility, larger documents will freeze or drop frames during interactive pans, zoom adjustments, or item drags.

---

## Alternatives Considered
1. **Immediate Painting**: Loop through all document items and draw directly on canvas.
   - *Con*: Unacceptable frame drop rates on large multi-page files.
2. **Fabric/Konva Grouping**: Delegate layer grouping to third-party canvas wrappers.
   - *Con*: Violates zero-dependency requirements. Heavy overhead.

---

## Decision and Consequences
We implemented a native, compiler-grade layout tree and Render Graph (`SceneNode`, `Scene`, `Camera`, `Viewport`). 

Document pages align in a vertical stack layout, with each page node containing default sub-layers (PDF, selection, annotation layers). Affine matrices propagate down node branches. 

During redraws, `RenderGraph` queries camera view matrices and active scroll viewports, checks `CullingManager` intersections to skip off-screen elements, and compiles a sorted Render Queue.

### Consequences:
* **Pros**: Decoupled compiler layout tree, culling optimizations, camera pans, and layout-independent page configurations.
* **Cons**: Marginally more complex coordinate calculations due to cascading world matrices.
